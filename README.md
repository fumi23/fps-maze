# FPS Maze — ブラウザで遊べる一人称視点の迷路

依存ライブラリなしの素の HTML + JavaScript(ES Modules)で動く、一人称視点の迷路探索。

## ▶ 遊ぶ

**<https://fumi23.github.io/fps-maze/>**(GitHub Pages)

PC + キーボード推奨。

現在のコースは **多層の3D迷路**。上下も本物の迷路軸なので、前後左右だけでは踏破できません。

| キー | 動作 |
| --- | --- |
| `W` / `S` | 前進 / 後退(1マス) |
| `A` / `D` | ヨー(左右90°旋回) |
| `R` / `F` | ピッチ(上下90°旋回) |
| `,` / `.` | ロール(画面内の傾き) |
| `Shift` + `A` / `D` | 左右ストレイフ(1マス) |
| `Shift` + `R` / `F` | 上下ストレイフ(1マス) |
| `←` / `→` `↑` / `↓` | ヨー / ピッチ(A/D・R/F の別名) |
| `M` | ミニマップを一時表示 |
| `Enter` | リスタート |

移動・旋回はグリッド単位の離散処理で、見た目はなめらかに補間されます(グリッドクロウラー方式)。
90度回転しかしないので、マウスロックや自由視点は不要です。

### 操作スキームの考え方

4次元まで一貫させるため、**単体キー = 旋回 / `Shift` = ストレイフ / 前後は単体で並進**
という統一スキームにしています。主役は「旋回 + 前進」で、ストレイフはオマケ。

旋回は「前をどの方向へ向けるか」で3種:ヨー(左右)・ピッチ(上下)・**フリップ**(表裏・4Dで追加)。
ロールは前を変えないので到達性には不要で、方向感覚の調整専用です。

このスキームは各次元へそのまま縮退します。2Dならヨーとストレイフだけが残り、
4Dでは `T` / `G` がフリップとして足されます。

## 設計の考え方

最終目標は **4次元迷路**。そのため、エンジンは最初から **N次元汎用** に設計してあり、
レンダラは「3D透視投影」1つで 2D / 3D / 4D すべてを描けるようになっています。

### 次元に依存しない状態

- **位置**: 整数ベクトル `number[]`(2Dなら長さ2、4Dなら長さ4)
- **向き**: カメラ基底 `[右, 上, 前, w, ...]`。各スロットに「その方向がワールドのどこを向くか」を
  符号付き単位ベクトルで持つ。90度回転は「2スロットの入れ替え+符号反転」で表現。

### レンダラは常に3D透視投影1つ

見えるのは「右 / 上 / 前」が指すワールド3軸だけ。それ以外の軸(4D以降の `w`)は
視界全体に直交していて**見えない**ので、「今いる `w` のスライス」に属するセルだけを描画します。

| 次元 | 見えるもの | 状態 |
| --- | --- | --- |
| 2D | 平面スライス | 位置(x,y) + 向き(前/右) |
| 3D | 空間まるごと | 位置(x,y,z) + 向き(前/上/右) |
| 4D | 現在の w のスライスのみ | 位置(x,y,z,w) + 向き(前/上/右/w) |

### コースは「モード記述子」で性格を変える

コースは迷路データに加えて、**どの回転面 / 並進方向を入力層で有効にするか**だけを持ちます。
エンジン側に分岐はなく、記述子が変わるだけで挙動が変わります。

```js
{ rotations: ["yaw", "pitch", "roll"], translations: ["fwd", "strafe", "up"] }
```

ヨーは up を保存するので、**ピッチ/ロールを割り当てないだけで到達姿勢が「直立の4通り」に閉じます**
(= 重力固定モードはフルエンジンの厳密な部分集合。ガードコードは不要)。
同じ3D迷路を「重力固定でクリア → 姿勢制御ありで解き直す」という難易度設計もできます。

### ミニマップは「相対 up スライス」

スライス面はプレイヤーの前後左右が張る平面、見るのは up 方向から見下ろす向きです。
90度回転しかしないので up は常にぴったり ±(世界軸)を向き、「どちら側から見下ろすか」が
一意に決まります(45度のような曖昧さが原理的に出ない)。

- **転置対策**: 地図の2軸は軸インデックス昇順で世界に固定。向きで割り当てが入れ替わらない
- **鏡像対策**: 画面上に置く軸の符号を up の符号から決め、俯瞰の手性に揃える
- 単一スライスでは縦の通路が見えないので、**up 軸方向の抜け道を ▲▼ で表示**します

重力固定コースでは up = 世界 up に固定されるので、この実装がそのまま普通のフロアプランになります。

### 壁だけを描く

迷路は「空セル / 壁セル」のグリッド。空セルが壁(または場外)と接する境界に、
単位正方形の面を1枚置いて描画します。テクスチャ・光源なし、面ごとの単色+距離フォグ。

## 開発

### ローカルで動かす

ES Modules を使うので、`file://` 直開きではなくローカルサーバー経由で開きます。

```bash
cd fps-maze
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

### ファイル構成

```
index.html            エントリ(canvas と HUD)
css/style.css         HUD/ヘルプ/ゴール表示のスタイル
src/
  vec.js              N次元ベクトル演算
  orientation.js      向き(カメラ基底)と90度回転
  maze.js             N次元グリッド迷路のデータモデル
  player.js           プレイヤー状態 + 移動/回転アニメ
  renderer.js         3D透視投影レンダラ(壁面を集めて描画)
  input.js            キーボード入力
  minimap.js          現在スライスの俯瞰ミニマップ(相対up)
  game.js             ループの組み立て(入力→更新→描画→HUD)+ キーバインド表
  main.js             起動
  courses/
    course1.js        コース1ローダ(N次元グリッド + モード記述子)
    course1.data.js   自動生成された静的マップ
tools/
  gen-maze.mjs        迷路生成プログラム(N次元 完全迷路 / 再帰的バックトラッカー)
```

### コースの作り直し

静的コースは生成プログラムで作っています。生成器は **N次元対応** で、
2D / 3D / 4D をすべて同じアルゴリズム(再帰的バックトラッカー)で作れます。

```bash
# 現在のコース1(3層の3D迷路)
node tools/gen-maze.mjs --dims 3 --rooms 6,3,6 --seed 8 > src/courses/course1.data.js
```

| オプション | 意味 |
| --- | --- |
| `--dims N` | 次元数(既定 3) |
| `--rooms a,b,c` | 軸ごとの部屋数。1つだけ渡すと全軸に適用。実グリッドは `2*部屋数+1` |
| `--seed N` | 乱数シード(同じ値なら同じ迷路) |
| `--braid 0..1` | 行き止まりをこの割合でつぶしてループを作る(0 = 完全迷路) |

難易度は **サイズ(`--rooms`)・次元数(`--dims`)・分岐の多さ(`--braid`)** で調整します。
`--braid` を上げるほど行き止まりが減り、「詰まりにくいが道を見失いやすい」迷路になります。

生成時に stderr へ通路数・到達セル数・ゴールまでの歩数が出るので、難易度の当たりを付けられます。
ゴールは「経路距離が上位のセルのうち直線距離が最大のもの」を選ぶので、
座標を頼りに進んでも達成感が出る位置になります。

出力フォーマットは次元非依存です。1行が axis0 方向の並びで、行インデックスは
axis1 を最上位に以降の軸を入れ子にしたもの(3Dなら 1ブロック = 1フロアの平面図)。
詳細は生成ファイル冒頭のコメントにあります。

### デバッグ(コンソール)

起動すると `window.game` にゲーム本体が公開されるので、コンソールから状態を触れます。
`game.debug` にテレポート系のヘルパーがあります。

```js
game.debug.nearGoal()          // ゴールの隣に置いてゴールを向く(W一歩でクリア)
game.debug.toGoal()            // ゴールに直接ワープ(即クリア)
game.debug.toStart()           // スタートに戻る
game.debug.teleport([x, y, z]) // 任意セルへ(壁なら拒否して警告)
game.debug.teleport([3, 3, 5], game.debug.goal()) // 移動してゴールの方を向く
game.debug.pos()               // 今の座標
game.debug.goal()              // ゴール座標
game.debug.minimap(true)       // ミニマップを常時表示(false で解除。通常は M の一時表示)
```

- 座標は `[X, Y, Z]`。今のコースは 13×7×13 で、通路がある層は Y=1〜5(部屋は奇数座標)。
- `teleport` は座標をN次元ベクトルとして扱うので、4D に拡張しても
  `game.debug.teleport([x, y, z, w])` のようにそのまま使えます。
- `nearGoal` は上下の隣接セルも探すので、縦穴の先にあるゴールでも機能します。
- そのほか `game.player`(位置・向き)、`game.maze`、`game.mode`、`game.renderer` に直接アクセス可能。
- HUD の `facing` / `up` が現在の姿勢そのもの(スナップ済み基底)なので、
  姿勢がおかしいと感じたときはここを見ます。

> `window.game` は `src/main.js` でゲーム本体をデバッグ用に公開しているものです。
