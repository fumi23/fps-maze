# FPS Maze — ブラウザで遊べる一人称視点の迷路

依存ライブラリなしの素の HTML + JavaScript(ES Modules)で動く、一人称視点の迷路探索。
GitHub Pages にそのまま置けます。

最終目標は **4次元迷路**。そのため、エンジンは最初から **N次元汎用** に設計してあり、
レンダラは「3D透視投影」1つで 2D / 3D / 4D すべてを描けるようになっています。

---

## 遊ぶ(ローカル)

ES Modules を使うので、`file://` 直開きではなくローカルサーバー経由で開きます。

```bash
cd fps-maze
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

### 操作

| キー | 動作 |
| --- | --- |
| `W` / `S` | 前進 / 後退(1マス) |
| `A` / `D` | 左右ストレイフ(1マス) |
| `Q` / `E` または `←` / `→` | 90°旋回 |
| `M` | ミニマップ表示切替 |
| `R` | リスタート |

移動・旋回はグリッド単位の離散処理で、見た目はなめらかに補間されます(グリッドクロウラー方式)。
90度回転しかしないので、マウスロックや自由視点は不要です。

## 設計の考え方

### 次元に依存しない状態

- **位置**: 整数ベクトル `number[]`(2Dなら長さ2、4Dなら長さ4)
- **向き**: カメラ基底 `[右, 上, 前, w, ...]`。各スロットに「その方向がワールドのどこを向くか」を
  符号付き単位ベクトルで持つ。90度回転は「2スロットの入れ替え+符号反転」で表現。

### レンダラは常に3D透視投影1つ

見えるのは「右 / 上 / 前」が指すワールド3軸だけ。それ以外の軸(4D以降の `w`)は
視界全体に直交していて**見えない**ので、「今いる `w` のスライス」に属するセルだけを描画します。

| 次元 | 見えるもの | 状態 |
| --- | --- | --- |
| 2D | 平面スライス | 位置(x,y) + 向き(前/右) |
| 3D | 空間まるごと | 位置(x,y,z) + 向き(前/上/右) |
| 4D | 現在の w のスライスのみ | 位置(x,y,z,w) + 向き(前/上/右/w) |

### 壁だけを描く

迷路は「空セル / 壁セル」のグリッド。空セルが壁(または場外)と接する境界に、
単位正方形の面を1枚置いて描画します。テクスチャ・光源なし、面ごとの単色+距離フォグ。

## ファイル構成

```
index.html            エントリ(canvas と HUD)
css/style.css         HUD/ヘルプ/ゴール表示のスタイル
src/
  vec.js              N次元ベクトル演算
  orientation.js      向き(カメラ基底)と90度回転
  maze.js             N次元グリッド迷路のデータモデル
  player.js           プレイヤー状態 + 移動/回転アニメ
  renderer.js         3D透視投影レンダラ(壁面を集めて描画)
  input.js            キーボード入力
  minimap.js          現在スライスの俯瞰ミニマップ
  game.js             ループの組み立て(入力→更新→描画→HUD)
  main.js             起動
  courses/
    course1.js        コース1ローダ(2Dグリッドを1層3Dに配置)
    course1.data.js   自動生成された静的マップ
tools/
  gen-maze.mjs        迷路生成プログラム(いまは2D。将来N次元へ)
```

## コースの作り直し

静的コースは生成プログラムで作っています。別のマップにしたいとき:

```bash
node tools/gen-maze.mjs --w 11 --h 11 --seed 7 > src/courses/course1.data.js
```

- `--w` / `--h`: 部屋数(実グリッドは `2w+1` × `2h+1`)
- `--seed`: 乱数シード(同じ値なら同じ迷路)

## デバッグ(ブラウザのコンソール)

起動すると `window.game` にゲーム本体が公開されるので、コンソールから状態を触れます。
`game.debug` にテレポート系のヘルパーがあります。

```js
game.debug.nearGoal()          // ゴールの隣に置いてゴールを向く(W一歩でクリア)
game.debug.toGoal()            // ゴールに直接ワープ(即クリア)
game.debug.toStart()           // スタートに戻る
game.debug.teleport([x, 1, z]) // 任意セルへ(壁なら拒否して警告)
game.debug.teleport([3, 1, 5], game.debug.goal()) // 移動してゴールの方を向く
game.debug.pos()               // 今の座標
game.debug.goal()              // ゴール座標
```

- 座標は `[X, Y, Z]`。今のコースは Y=1 の1層なので中央は常に 1、水平は X と Z。
- `teleport` は座標をN次元ベクトルとして扱うので、3D / 4D に拡張しても
  `game.debug.teleport([x, y, z, w])` のようにそのまま使えます。
- そのほか `game.player`(位置・向き)、`game.maze`、`game.renderer` に直接アクセス可能。

> `window.game` はデバッグ用途の公開です。不要になったら `src/main.js` の該当行を消してください。

## GitHub Pages で公開

ビルド不要。リポジトリ直下に `index.html` があるので、そのまま公開できます。

1. GitHub にリポジトリを作って push
2. **Settings → Pages → Build and deployment**
3. Source を **Deploy from a branch**、Branch を `main` / `/ (root)` に設定
4. 数分後 `https://<user>.github.io/<repo>/` で公開される

> ES Modules は https 経由なら正しい MIME で配信されるのでそのまま動きます。

## これから(ロードマップ)

1. **今ここ**: 1層3Dコースで見え方・操作感を作り込む
2. 上下移動 + 上下90度回転(ピッチ)を追加 → **真の3D迷路**
3. w軸の移動 + 回転を追加 → **4D迷路**
4. 生成プログラムを N 次元対応にし、難易度違いの複数コースを用意

### 作り込みでいじれるパラメータ

- `src/game.js`: `new Renderer(canvas, { fov: 75 })` … 視野角
- `src/player.js`: `moveDur` / `turnDur` … 移動・回転の所要時間(操作のキビキビ感)
- `src/renderer.js`: 色パレット、`maxDist` / `fogStart` / `fogEnd` … 描画距離とフォグ
